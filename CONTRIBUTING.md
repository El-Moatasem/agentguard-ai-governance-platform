# Contributing Workflow

This is a solo capstone project, but it uses a professional review workflow for evidence.

1. Create one GitHub issue per task or user story.
2. Create a branch named `feature/<short-name>` or `fix/<short-name>`.
3. Open a pull request into `main`.
4. Attach screenshots for UI work and test output for backend changes.
5. Merge only when checks pass.

## Definition of Done

- User story acceptance criteria met.
- Unit or integration tests added where relevant.
- Documentation updated when architecture, API, or deployment behavior changes.
- No known critical security issue remains unresolved.
