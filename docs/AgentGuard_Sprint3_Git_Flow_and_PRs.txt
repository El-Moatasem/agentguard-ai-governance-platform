AGENTGUARD SPRINT 3 - GIT FLOW AND PULL REQUEST GUIDE
Version target: v0.3.0

PURPOSE
=======
This guide maps the Sprint 3 Jira epic/stories/tasks to a practical Git and pull-request workflow. The recommended approach uses five feature PRs into Sprint-3, followed by Sprint-3 -> develop and develop -> main release PRs.

Sprint 3 Jira epic:
300 - AG Sprint 3 - Human Approval, Real Agent/MCP, and AI Explanations

Recommended feature PR grouping:

PR 1 - Stories 310 + 320
  310 Complete the human approval lifecycle
    311 Implement approval queue and detail APIs
    312 Implement approve, reject, expire, and cancel transitions
    313 Prevent self-approval and duplicate processing
  320 Execute governed tools safely
    321 Create provider-neutral tool adapter interface
    322 Add idempotent execution records
    323 Handle tool timeout, failure, and retry safely

PR 2 - Stories 330 + 340
  330 Integrate a real AI agent
    331 Implement agent adapter and structured request schema
    332 Register agent identity and permitted capabilities
    333 Add mock mode for deterministic local and CI testing
  340 Integrate one MCP tool provider
    341 Configure MCP client and secret handling
    342 Allowlist safe MCP tools and argument schemas
    343 Implement MCP mock server or stub

PR 3 - Stories 350 + 360
  350 Explain policy decisions with AI without changing them
    351 Create model-provider abstraction and mock provider
    352 Build grounded explanation prompt and output schema
    353 Handle AI provider failure safely
  360 Add agent and MCP security guardrails
    361 Validate and sanitize tool arguments
    362 Add prompt-injection and bypass test cases
    363 Redact secrets and sensitive fields from logs and prompts

PR 4 - Story 370
  370 Provide an end-to-end governance interface
    371 Build approval queue and review screens
    372 Display execution timeline and correlation data
    373 Display grounded AI explanations and failure states

PR 5 - Story 380
  380 Test, document, and demonstrate Sprint 3
    381 Add approval, agent, MCP, and end-to-end tests
    382 Update architecture, threat model, and AI evaluation docs
    383 Create Sprint 3 release notes and demo evidence

IMPORTANT WORKFLOW RULES
========================
1. Create Sprint-3 from the latest develop branch after v0.2.0 is released.
2. Every feature branch starts from the latest Sprint-3 after the previous feature PR has been merged.
3. Every feature PR targets Sprint-3, not develop or main.
4. Only mark the related Jira stories/tasks Done after the PR is merged and verified.
5. Preserve your existing .git directory. Never copy another .git directory into the repository.
6. Do not commit .env, .venv, node_modules, local databases, __pycache__, .DS_Store, API keys, or MCP credentials.
7. The Sprint 3 ZIP is cumulative/reference source. Review and integrate the relevant changes for each PR rather than claiming unrelated changes under the wrong story.
8. Shared files such as models.py, schemas.py, main.py, config.py, seed.py, and frontend main.tsx may contain changes for more than one story. Use `git add -p` when necessary so each PR contains only the intended hunks.

STEP 1 - CREATE THE SPRINT-3 INTEGRATION BRANCH
===============================================
Start from the released and synchronized develop branch.

Commands:

```bash
git switch develop
git pull origin develop

git switch -c Sprint-3
git push -u origin Sprint-3
```

Verify:

```bash
git branch --show-current
git status
git log --oneline --decorate -10
```

Expected current branch:

```text
Sprint-3
```

Jira action:
- Start Sprint 3.
- Move Epic 300 and the first active stories to In Progress.

OPTIONAL - PRESERVE THE CUMULATIVE SPRINT 3 ZIP AS A LOCAL SNAPSHOT
==================================================================
If you already copied the entire v0.3.0 source into your repository, preserve it before splitting work.

```bash
git switch -c sprint3-full-snapshot
git add -A
git commit -m "WIP: preserve complete Sprint 3 implementation"
```

Do NOT merge this branch and do NOT use it as Capstone evidence. It is only a local safety/reference branch.

Return to the clean Sprint-3 branch:

```bash
git switch Sprint-3
git status
```

If you need to compare a shared file with the cumulative source:

```bash
git diff Sprint-3..sprint3-full-snapshot -- apps/api/app/models.py
git diff Sprint-3..sprint3-full-snapshot -- apps/api/app/schemas.py
```

For shared files, stage only the hunks that belong to the current PR:

```bash
git add -p apps/api/app/models.py
git add -p apps/api/app/schemas.py
git add -p apps/api/app/main.py
```
